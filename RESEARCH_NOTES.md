# Research notes (NeoForge 1.21.1)

- Create dependency guidance: https://wiki.createmod.net/developers/depend-on-create/neoforge-1.21.1 — Create 6.0.10 / MC 1.21.1, `create_version=6.0.10-280`, Registrate `MC1.21-1.3.0+67`, Create Maven `https://maven.createmod.net`, Registrate Maven `https://maven.ithundxr.dev/snapshots`.
- Create 1.21.1 upstream code: https://github.com/Creators-of-Create/Create/blob/mc1.21.1/dev/src/main/java/com/simibubi/create/Create.java ; `CreateRegistrate.create(ID)` singleton and `registerEventListeners(modEventBus)` pattern.
- Create train API code: https://github.com/Creators-of-Create/Create/blob/mc1.21.1/dev/src/main/java/com/simibubi/create/content/trains/entity/Navigation.java ; https://github.com/Creators-of-Create/Create/blob/mc1.21.1/dev/src/main/java/com/simibubi/create/content/trains/entity/Train.java ; https://github.com/Creators-of-Create/Create/blob/mc1.21.1/dev/src/main/java/com/simibubi/create/content/trains/graph/TrackGraph.java . `Navigation.findPathTo` already considers both graph directions. `Train.crash()`/`disassemble()` are public; collision implementation is private and direct field graph mutation is fragile.
- Sable API sources: https://github.com/ryanhcode/sable ; checked local 2.0.7 tree for MC1.21.1. Public `SubLevelAssemblyHelper.assembleBlocks(ServerLevel, BlockPos, Iterable<BlockPos>, BoundingBox3ic)` moves blocks/entities into a Sable sublevel. `RigidBodyHandle.addLinearAndAngularVelocity(...)` and impulse methods allow velocity/impulse adjustments.
- CCD in Sable's native Rapier integration is enabled by default in the Rust body builder; `max_ccd_substeps=3`. There is no public Java API to toggle CCD per entity/speed. Do not claim a configurable >50 m/s switch without changing Sable itself.
- Sable exposes no TrackGraph/train detachment API. Sable assembly helper is not a substitute for Create's train graph lifecycle.

## Additional Sable API audit (local source 2.0.7, MC1.21.1)

- Repository source roots: https://github.com/ryanhcode/sable and https://github.com/ryanhcode/sable-companion.
- `SubLevelAssemblyHelper.assembleBlocks(...)` in `dev.ryanhcode.sable.api` requires a `ServerLevel`, world `BlockPos` anchor, actual iterable world `BlockPos` blocks, and bounds. It calls `SubLevelContainer.getContainer(level).allocateNewSubLevel(pose)`, initializes plot, physically moves existing world blocks and tracking points. A Create train carriage's contraption blocks are held in contraption data, not world positions, so this helper cannot safely be passed those blocks as-is.
- `SubLevelHelper` has entity projection, query, and velocity helpers; it has no public new-sublevel factory. `SableCompanion` exposes query/projection/velocity utilities, not sublevel creation. `EntityMovementExtension` only exposes tracking-sublevel state/collision info; no create/assemble or rigid-body impulse API.
- `ServerSubLevel` has a public constructor but its own documentation says create/allocate it through the container; direct constructor omits allocation/plot/physics initialization and should not be used.
- Therefore leave a TODO conversion seam in the derail hook; do not build a fake sublevel from a train entity. `Train.detachFromTracks()` records Create track migration points, sets graph null, and is a detach primitive, not a permanent Sable conversion. A permanent derail path must prevent Create migration/re-attachment and implement Sable-compatible physics lifecycle before production use.

## Follow-up verification (22 Nov 2026)

- Create's `CreateRegistrate.setCreativeTab(...)` records a registry entry's tab association; it does not itself populate an arbitrary mod-owned `CreativeModeTab`. Create's own `AllCreativeModeTabs` supplies a `RegistrateDisplayItemsGenerator` that iterates registered entries and filters them with `CreateRegistrate.isInCreativeTab(...)` (`CreateRegistrate.java` and `AllCreativeModeTabs.java`, Create `mc1.21.1` source). Therefore an empty `.displayItems(...)` callback is a valid way to avoid duplicate inserts, but the custom tab may contain no items unless another generator adds them; `.simpleItem()` alone is not proof of automatic population.
- Inspected the project's resolved `maven.modrinth:sable:2.0.6+mc1.21.1` JAR directly. It contains `SubLevelAssemblyHelper`, `SubLevelContainer`, `PhysicsPipeline`, and `EntityMovementExtension` classes. Local Sable source tree is 2.0.7, where signatures include `assembleBlocks(ServerLevel, BlockPos, Iterable<BlockPos>, BoundingBox3ic)`, `allocateNewSubLevel(Pose3d)`, `addLinearAndAngularVelocity(...)`, and `sable$setTrackingSubLevel(SubLevel)`. The method-level binary compatibility of 2.0.6 was not independently verified; class presence does not solve the Create contraption-to-world-block conversion gap.
- Create's `Contraption` stores carriage structure block data separately from ordinary world positions. `SubLevelAssemblyHelper` operates on ordinary world blocks; calling it on these stored positions would not assemble the carriage structure. Disassembling first materializes the blocks but also changes Create's carriage/passenger lifecycle, and no validated transaction was found that preserves the train, passengers, and permanent derail state. Do not represent `detachFromTracks()` alone as Sable physics: it stores migration data and can permit later reattachment.
